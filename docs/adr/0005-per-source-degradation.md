# ADR-005: 单源故障分源降级，图标与告警由健康源继续计算

- 状态：已接受（2026-08-12，架构复盘质询轮 3）
- 关联：[[0003-auth-expiry-notification]]、[[0004-overall-percent-min-semantics]]、[[glossary]]

## 背景

现状是 fail-closed 整体降级：`HasError` 判定任一源（AuthFailed / 解析失败 / 网络错误）
出错即成立，整体 percent 置空 → 整颗图标置灰，且 50/30/10 告警对 null 直接静默。
后果：Go 页面改版导致解析失败时，ChatGPT 即使只剩 6% 也不告警、不显色——故障源
把健康源的信号一起埋葬。与 ADR-003 按源独立通知的分源思路相悖。

## 决策

- **fail-partial 分源降级**：某源故障时该源单独置灰并显示状态文字（tooltip / 详情窗不变，
  已有分源明细），**图标颜色与 50/30/10 告警继续由健康源计算**。
- 聚合语义不变（ADR-004 的 min）：`OverallPercent` 从"所有窗口的 min"改为
  **"健康窗口的 min"**——故障源的窗口从聚合中剔除，不拖垮整体。
- AuthFailed 的显式通知仍由 ADR-003 的 balloon 负责；解析/网络错误在 tooltip 可见，
  下一次刷新（10 分钟内）自动恢复后无需任何干预。
- 全源故障（两个源都失败）时整体仍置灰——"完全不可信"的语义保留。

## 影响

- 正向：故障期间健康源的颜色与告警继续工作；单源故障不再是整体静默。
- 负向：绿色图标不再代表"全部正常"，而是"至少一个源正常"——语义弱化由 tooltip
  的分源状态文字补偿；实现改动集中在 `HasError` / `OverallPercent` 的按源剔除。

## 验收标准

- 单源故障（如解析失败）→ 图标颜色与告警由另一健康源驱动；tooltip 显示故障源状态文字。
- 双源均故障 → 图标置灰，与现状一致。
- 故障源恢复（下次刷新）→ 自动回到全量聚合，无人工干预。
