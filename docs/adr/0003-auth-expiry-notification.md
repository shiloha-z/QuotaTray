# ADR-003: 登录失效弹系统通知，失效段内只提示一次

- 状态：已接受（2026-08-12，架构复盘质询轮 2）
- 关联：[[0001-hidden-webview2-on-demand]]、[[0002-credential-store-marker-only]]、[[glossary]]

## 背景

登录失效（401/403）现状：图标置灰 + 详情窗文字提示，**无任何系统通知**——数据直接停更却完全
沉默；重启应用后首登判定只查"是否登过"（`Read() != null`，见 ADR-002 的标记语义），不查
"是否仍有效"，因此失效状态在重启后继续静默。README 已将此列为已知限制。

## 决策

- 刷新检测到某数据源从"正常"转为 `AuthFailed`（401/403）时，弹一次系统通知
  （如 "ChatGPT 登录已失效，请右键重新登录"），**按源独立标记**（chatgpt / go 各一次）。
- **失效段内只弹一次**：复用余量告警的"档位标记"模式（见 [[glossary]] 告警档位）——
  该源刷新成功（重新登录后）即重置标记，允许下次失效再次通知。
- 状态**仅存运行时**，不持久化：启动后第一次刷新（数秒内）即可发现失效并提示。
- 不自动弹登录窗（避免打断/风控），重登仍走右键菜单。

## 影响

- 正向：登录失效从"沉默故障"变为"一次性显式提示"；实现成本低（复用 `ShowBalloonTip` 模式）。
- 负向：无——通知频率受"失效段内一次"约束，不会刷屏。

## 验收标准

- 失效 → 通知一次；再次失效（未重登）不重复通知。
- 重新登录成功 → 再次失效时重新通知。
- 通知文案区分数据源。
